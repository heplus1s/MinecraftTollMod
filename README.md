# MinecraftTollMod · 通行收费模组

Fabric 1.20.1 服务端收费点原型。配合 MinecraftBankMod / MinecraftLandMod，用一条命令在当前位置创建收费点；玩家经过时逐人向指定账户支付固定金额。**当前为待联机验收的初版，不应直接部署生产存档。**

## 安装

Java 17、Fabric Loader ≥0.15.11、Fabric API 0.92.2+1.20.1、MinecraftBankMod（必须提供 `TollSettlement.loadState/saveState` 的权威检查点接口及收费结算接口，旧订单还需保留 `MarketSettlement.transfer`）。将 jar 放进服务器 mods。客户端无需安装收费模组；没有自定义方块、物品或客户端网络包。其他已装模组仍须分别满足原版客户端兼容性。

## 一条命令建点

新建点不必命名，系统自动生成稳定编号：

```mcfunction
/toll private "央行券" 3
/toll system "央行券" 3 8 2 3
```

参数：`币种 金额 [水平半径 [向下范围 向上范围]]`。默认半径3格，向下2格、向上2格。位置取执行玩家当前位置，控制台暂不能创建。中文名称、带冒号ID用英文双引号，重名货币使用 `"id:货币ID"`。

- `private`：普通玩家在自己领地创建，收款到本人银行账户。圆形区域相交的每个区块都必须归本人；创建和每次产生新订单时复核。缺少领地接口、土地转手或部分不属于自己时不收费。不把受邀权限视作土地所有权。
- `system`：仅管理员权限等级2，入银行专用收费系统账户。必须有新版 `TollSettlement.collectSystem` 接口；不伪造玩家UUID替代系统账户。创建时只读预检当前结算精度/准备金链，不可结算则拒绝创建；汇率日后变化仍需每次交易重验，精度或准备金不足不会视为玩家欠费。
- 央行券/个人币最多4位小数，实物货币整数，正金额不超过1,000,000,000。新版银行提供个人币目录与结算，旧接口只允许基础币整数转账。
- 半径1–128格，上下范围各0–128格但不能同时为0。范围变更暂需删除后重建。
- 拥有者可查看、删除自己的点，管理员可管理全部点。本人通过自己的私人点不扣款。

```mcfunction
/toll list
/toll info "返回的收费点编号"
/toll remove "返回的收费点编号"
```

旧管理员命令 `/toll create "名称" 半径 "币种" 整数金额 在线玩家或UUID` 为已有原型兼容保留，上下各4格。删除点不取消已产生的订单，未知结果继续按同一订单引用恢复，而非生成新扣款。

收费点以原版文本展示实体显示每人金额、币种、水平半径与上下范围。只维护已加载区块，不强制加载区块；每秒同步，稳定实体UUID防重，删除点的旧实体在区块加载后清理。

## 计费规则

- 圆柱形范围，按玩家收费，不按船数收费。步行、矿车、冰船通过均适用；旁边道路应避开范围。
- 每次进入一次固定费用，不自动计算公里；可按每段里程设置不同金额/收费点。
- 每 tick 检查上次到当前位置的线段，高速穿越且两端都在圈外也能触发。
- 离开半径 +2、上下高度 +2 的缓冲范围后，在下一次每秒检查时重新启用。圈内停留、边缘晃动不连扣；很快折返会有约一秒去重窗口。
- 新建点、登录、重启恢复、维度变化或正常服务端传送后，已经在圈内的人不会补扣。单 tick 位移超过 64 格按异常位移处理而不计费。**这不是防作弊系统**，其他模组绕过正常传送接口、瞬移/重新登录等仍需服主管理。
- 收费区及横向缓冲不允许重叠。最多 128 个点、10000 条历史订单，达到订单上限暂停，须由管理员审核归档后再运行；初版保存为整份 JSON，同步磁盘写入，适合小规模试运行，未做高并发性能认证。
- 浮标会显示费用和范围，但仍需服主建设安全下船平台。

## 银行异常与扣船

先保存订单、唯一引用及固定结算协议，再调用银行。旧存档缺少协议字段时固定使用原 MarketSettlement，新订单记录选中的协议；升级不能切换旧订单协议，降级缺少现代接口时保持待恢复，绝不换接口重扣。银行未知、桥接异常、保存待确认等状态保留 `PENDING`，每 5 秒使用**相同引用**重试。不会把内存回执当作已持久化证明，也不会把未知结果当作余额不足。收费点配置、去重状态和订单JSON通过版本比较更新写入银行同一检查点。先提交PENDING，再执行银行扣款；扣款检查点同时携带PENDING，最后更新PAID。重启即便恢复到PENDING，也在同一本账内按原协议和引用核验，不再依赖第二个文件判断是否扣款。

明确 `insufficient_funds` 时记录欠费；有船且欠费者仍乘坐同一艘船才尝试没收。双人船分别扣费，其中一人不足会没收整艘船，已付款乘客不会自动退款。步行和矿车欠费仅记录、提示，不拦路、不扣矿车。

普通船没收前检查附近已加载位置有实心非岩浆块/仙人掌地板和两格空气，存下船实体类型和完整 NBT，保存成功才下客并移除船，不产生掉落物。找不到位置时保留船，在本次过路5秒窗口内继续尝试；并非任何复杂地形都保证找到安全出口。船会继续保留碰撞/玩家操控能力，因此此延迟机制不是强制封锁。

**箱船本版明确不没收、不移除、不抽取物品，只记录欠费并提示联系管理员。** 在可靠领取/恢复流程完成并验证前，避免以“存档保全”代替玩家实际可取回的库存。该安全例外意味着箱船仍可继续行驶，不具备自动强制追缴能力。

普通船处置仅限本次过路5秒窗口，且欠费者仍乘坐原船。离船、离线、超时或服务器重启后转人工核查，不在之后重新上船时追缴；结果未知的订单可继续幂等结算，但不会重新打开没收窗口。扣押记录不自动生成第二艘船；管理员恢复必须先确认原船是否存在，避免复制。

持久化：新版以银行检查点中的收费状态为唯一权威。首次启动仅在银行明确没有收费状态时，从`世界目录/data/tollmod/state.json`迁移旧原型配置及订单；原始旧文件备份为`state.json.pre-bank-migration`，原路径写入schema=2兼容性防护标记，旧收费jar会拒绝读取。该标记不是资金账本，不再把本地文件作为恢复备选。银行状态损坏、接口缺失、版本冲突、保存失败或状态不明时暂停，不回退旧文件，不重建未知订单。银行与收费包须配套升级，已迁移世界禁止运行旧收费jar或旧银行。兼容性标记能阻止正常误回滚，但无法防管理员删除标记、恢复旧目录或硬件回滚；这些情况必须停服人工核账，不能宣称自动防重复。

旧JSON的导出/迁移测试写入工具仍使用文件同步、原子替换、父目录同步；它不参与新版正常收费，所以Windows不必为了收费强行打开目录句柄。共享银行检查点避免资金与过路订单跨文件一边恢复一边丢失的问题，但不声称能防止磁盘硬件违背刷新承诺、整存档回滚或管理员删除数据。仍应停服完整备份。

## 构建与验证

```sh
./gradlew build
```

GitHub Actions 使用 Java 17 构建并上传 jar。JUnit 覆盖穿越几何、楼层过滤、中文币种/歧义、订单引用和去重持久化、损坏文件拒绝。

原始原型曾通过 GitHub Actions；本次扩展尚未完成完整 Fabric 构建与联机验收，本地独立核心 JUnit 测试已通过35项。不能将旧 CI 结果视为本次构建通过。发布前必须验证：

1. 原版 1.20.1 客户端登录，带模组客户端登录；
2. 双人高速船、箱船库存、足额/不足、上下层和缓冲折返；
3. 银行写盘失败、收费状态CAS冲突、重启重试不重复扣款；
4. 传送、断线、移除收费点、无安全下船点、归档后崩溃恢复；
5. 实际存档的扣押恢复和备份还原流程。
