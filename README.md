# MinecraftTollMod · 通行收费模组

Fabric 1.20.1 服务端收费点原型。配合 MinecraftBankMod，管理员用一条命令在当前位置创建收费点；玩家经过时逐人向指定账户支付固定金额。**当前为待联机验收的初版，不应直接部署生产存档。**

## 安装

Java 17、Fabric Loader ≥0.15.11、Fabric API 0.92.2+1.20.1、MinecraftBankMod（必须提供 `MarketSettlement.transfer` 的引用幂等与保存失败重试接口）。将 jar 放进服务器 mods。客户端无需安装收费模组；没有自定义方块、物品或客户端网络包。其他已装模组仍须分别满足原版客户端兼容性。

## 一条命令建点

站在收费区域中心执行（管理员权限等级 2）：

```mcfunction
/toll create "高速东线" 8 "银行券" 3 Steve
```

含义：当前维度、当前坐标，水平半径 8 格、上下各 4 格；每人每次穿越收取 3 银行券，转入在线玩家 Steve 的银行账户。收款人也可直接填写离线 UUID。金额是该币种的整数账本单位，**不是折算后的铜锭金额**。

```mcfunction
/toll create "高速西线" 6 "id:note" 5 00000000-0000-0000-0000-000000000001
/toll info "高速东线"
/toll list
/toll remove "高速东线"
```

**中文名称、中文币名及带冒号的 `id:note` 请加英文双引号**，这是原版 Brigadier 字符串参数的要求。收费点名最多 64 字符，半径 1–128，整数金额 1–1,000,000,000。上下高度固定 4 格，初版不提供修改命令；需要改动时删除再创建。删除不取消已产生的订单或欠费处置。

币种从银行当前注册币种读取并提供补全，保存稳定 ID。中文同名时拒绝创建，使用 `"id:货币ID"` 明确指定。不会把“中央银行券”猜成“银行券”，也不会把不支持的个人券冒充银行结算币种。收款人自己通行时银行会拒绝同账户转账，不产生扣款或没收。

## 计费规则

- 圆柱形范围，按玩家收费，不按船数收费。步行、矿车、冰船通过均适用；旁边道路应避开范围。
- 每次进入一次固定费用，不自动计算公里；可按每段里程设置不同金额/收费点。
- 每 tick 检查上次到当前位置的线段，高速穿越且两端都在圈外也能触发。
- 离开半径 +2、上下高度 +2 的缓冲范围后，在下一次每秒检查时重新启用。圈内停留、边缘晃动不连扣；很快折返会有约一秒去重窗口。
- 新建点、登录、重启恢复、维度变化或正常服务端传送后，已经在圈内的人不会补扣。单 tick 位移超过 64 格按异常位移处理而不计费。**这不是防作弊系统**，其他模组绕过正常传送接口、瞬移/重新登录等仍需服主管理。
- 收费区及横向缓冲不允许重叠。最多 128 个点、10000 条历史订单，达到订单上限暂停，须由管理员审核归档后再运行；初版保存为整份 JSON，同步磁盘写入，适合小规模试运行，未做高并发性能认证。
- 必须自行设置可见告示、票价与安全下船平台。命令没有自动生成收费标志。

## 银行异常与扣船

先保存订单和唯一引用，再调用银行。银行未知、桥接异常、保存待确认等状态保留 `PENDING`，每 5 秒使用**相同引用**重试。不会把内存回执当作已持久化证明，也不会把未知结果当作余额不足。银行和收费点各自保存，不宣称跨文件事务具备数据库级原子性。

明确 `insufficient_funds` 时记录欠费；有船且欠费者仍乘坐同一艘船才尝试没收。双人船分别扣费，其中一人不足会没收整艘船，已付款乘客不会自动退款。步行和矿车欠费仅记录、提示，不拦路、不扣矿车。

普通船没收前检查附近已加载位置有实心非岩浆块/仙人掌地板和两格空气，存下船实体类型和完整 NBT，保存成功才下客并移除船，不产生掉落物。找不到位置时保留船，继续尝试；并非任何复杂地形都保证找到安全出口。船会继续保留碰撞/玩家操控能力，因此此延迟机制不是强制封锁。

**箱船本版明确不没收、不移除、不抽取物品，只记录欠费并提示联系管理员。** 在可靠领取/恢复流程完成并验证前，避免以“存档保全”代替玩家实际可取回的库存。该安全例外意味着箱船仍可继续行驶，不具备自动强制追缴能力。

未完成的普通船没收可在之后发生，但只对原船且欠费者仍乘坐时处理，不追缴其他船。扣押记录不自动生成第二艘船；管理员恢复必须先确认原船是否存在，避免复制。

保存文件：`世界目录/data/tollmod/state.json`。包含点配置、订单、去重状态和扣押记录。写临时文件并刷新、原子替换；不支持原子替换或保存出错即暂停收费。损坏文件不覆盖重置。应把银行与该文件一起停服备份；突然断电的文件系统持久化、银行存档回滚等风险不能仅靠模组消除。

## 构建与验证

```sh
./gradlew build
```

GitHub Actions 使用 Java 17 构建并上传 jar。JUnit 覆盖穿越几何、楼层过滤、中文币种/歧义、订单引用和去重持久化、损坏文件拒绝。

当前本地独立核心测试已通过 10 项，完整 Fabric 构建受依赖下载限制尚未完成，不代表已通过 Minecraft 联机实测。发布前必须验证：

1. 原版 1.20.1 客户端登录，带模组客户端登录；
2. 双人高速船、箱船库存、足额/不足、上下层和缓冲折返；
3. 银行写盘失败、收费文件写盘失败、重启重试不重复扣款；
4. 传送、断线、移除收费点、无安全下船点、归档后崩溃恢复；
5. 实际存档的扣押恢复和备份还原流程。
